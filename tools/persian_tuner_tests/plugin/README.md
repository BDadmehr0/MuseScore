# Persian Tuner - علامت‌محور (Sign-Oriented)

**Persian Tuner is a built-in dock panel**, opened from **View ▸ Persian Tuner**,
the same way as Mixer. It docks inside the main window and can be attached to
other panels. This folder is kept only for logic tests.

A sign-oriented tuner: notes in **cents relative to natural of the same letter**.  
هر نت با **حرف + علامت** (مثلاً لا کرن، می سری) شناخته می‌شود و سنت آن **نسبت به بکار همان حرف** سنجیده می‌شود.

> **منطق جدید طبق نظر کارفرما:**  
> - کاربر نت را انتخاب می‌کند (مثلاً لا)  
> - در پنل کناری، علامت را انتخاب می‌کند (بمل، کرن، بکار، سری، دیز)  
> - سنت را تنظیم می‌کند، مبنا همیشه **بکار همان حرف** است. مثلاً لا کرن = ‎-50¢ نسبت به لا بکار.  
> - دستگاه (همایون، شور...) نداریم؛ فقط **علامت** مهم است. علامت در طول قطعه می‌تواند بشکند/تغییر کند.  
> - مارکر به جدول لینک است: «از اینجا تا اینجا، فلان علامت این صدا را بده، بقیه دیفالت».

## جدول کوک علامت‌محور

- **حرف نت:** C D E F G A B (دو، ر، می، فا، سل، لا، سی)
- **علامت‌ها:**  
  - بمل ♭ = ‎-100¢ نسبت به بکار  
  - کرن 𝄳 = ‎-50¢  
  - بکار ♮ = ‎0¢  
  - سری 𝄲 = ‎+50¢  
  - دیز ♯ = ‎+100¢  
  همه قابل تنظیم دقیق (مثلاً کرن -48 یا سری +53).

- **مبنا:** بالای هر ردیف نوشته شده: «مبنا: لا بکار» یعنی تمام مقادیر نسبت به لا بکار سنجیده می‌شوند.  
  مثال: لا کرن -45 یعنی 45 سنت بم‌تر از لا بکار.

- **ذخیره:** جدول به صورت JSON در تنظیمات پلاگین ذخیره می‌شود و با `ذخیره جدول / بارگذاری جدول` قابل نگهداری است.

## حافظه خودکار (Automatic memory)

- مقداری که برای یک علامت وارد می‌کنید (مثلاً لا کرن = ‎-45) به خاطر سپرده می‌شود.
- از همان نقطه به بعد، هر جای قطعه که همان علامت بیاید، همان مقدار اعمال می‌شود.
- اگر جای دیگری مقدار را عوض کنید (مثلاً میزان 40، لا کرن = ‎-40)، از همان‌جا به بعد مقدار جدید اعمال می‌شود.
- حافظه بر اساس **حرف + علامت** است، نه فقط pitch class. یعنی لا کرن و لا بکار دو کلید جدا هستند.
- گزینه‌ها:
  - `حرف + علامت` (پیش‌فرض): لا کرن ≠ لا بکار
  - `حرف نت`: همه لا‌ها یکسان
  - `جدا برای هر حامل`: حافظه جدا برای هر Staff

دکمه‌ها:
- **Re-apply**: اعمال مجدد کل حافظه به قطعه
- **Clear memory**: پاک کردن حافظه این قطعه
- **Use remembered**: اعمال مقدار به خاطر سپرده شده به انتخاب

## مارکر - لینک به جدول

مارکر نقطه‌ای است که از آنجا به بعد، یک علامت خاص با کوک جدید صدا می‌دهد.

1. دکمه **⚑ Marker** را بزنید (نقطه نارنجی روشن).
2. روی نتی در پارتیتور کلیک کنید.
3. مارکر بالای نت ثبت می‌شود، پنجره جلو می‌آید.
4. مقدار سنت را (نسبت به بکار) وارد کنید و Enter بزنید.

مارکر در پارتیتور می‌ماند (مستندسازی). بخش **مارکرهای کوک** فهرست آن‌ها را با **برو** و **حذف** نشان می‌دهد.

منطق مارکر = حافظه خودکار + نشانه بصری. هر مارکر یک ورودی در حافظه است: `{tick, cents}` برای کلید `A/koron`.

## کوک انتخاب

- فیلد سنت: مقدار هدف نسبت به بکار (مثلاً -50 برای کرن).
- پیش‌نمایش زنده هنگام تایپ، اعمال نهایی با Enter.
- دکمه‌های سریع: کرن -50، بکار 0، سری +50.
- لیست نت‌های انتخاب شده: هر نت با حرف + علامت + سنت هدف + تیونینگ مورد نیاز (required = target - base).

فرمول:
```
requiredTuning (note.tuning) = targetCentsRelativeToNatural - baseCentsOfVariant
```
مثلاً لا کرن با هدف -45: base = -50، required = -45 - (-50) = +5¢

## برای توسعه‌دهنده‌ها

- `tunerlogic.js`: منطق خالص بدون وابستگی Qt/MuseScore:
  - `NOTE_LETTERS`, `ACC_VARIANT_DEFS`, `defaultTuningTable()`, `getTuning()`, `setTuning()`
  - `noteIdentityFromNote()`, `makeSignKey()`, `baseCentsForVariant()`, `requiredTuning()`
  - حافظه: `newStore()`, `setChange()`, `resolveCents()`, `indicesToTune()`
  - مارکر: `markerText()`, `parseMarkerText()`
- تست‌ها: `tools/persian_tuner_tests` (نیاز به PySide6). منطق جدید علامت‌محور تست شده.

```sh
./tools/persian_tuner_tests/run_tests.sh
```

## تفاوت با نسخه دستگاه‌محور

- نسخه قدیمی: پیش‌فرض دستگاه (همایون، شور...) و اعمال به درجات گام نسبت به تونیک.
- نسخه جدید: **بدون دستگاه**، فقط **علامت**. هر علامت (حرف + کرن/سری/...) جداگانه قابل تنظیم است و سنت نسبت به بکار همان حرف سنجیده می‌شود. این دقیقاً همان منطق پنل `cent-tuning-panel.html` کارفرما است.
